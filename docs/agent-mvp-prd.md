# Skillberry Agent 工作台需求文档

状态为评审稿 · 2026-11-24

## 1. 产品目标

用户可以新建项目，在项目内发起多个任务，让 Agent 在项目专属 Sandbox 中处理文件，并在对话中查看执行过程和结果。用户回到旧任务可以继续对话，也可以在同一项目里开启一个新任务，复用项目文件。首版先验证这条流程，为后续在项目中启用 Skill 打好基础。

当前仓库已安装 Next.js 16.4.6、AI SDK 7.0.181 和 `@ai-sdk/react` 4.0.186，shadcn/ui 使用 `base-nova`。首页仍是 Next.js 初始化页面，项目与任务存储、Harness 接入和聊天界面待建设。依据 [package.json](../package.json)、[组件配置](../components.json) 和 [当前首页](../app/page.tsx)。

## 2. 项目、任务和执行的关系

| 概念 | 首版定义 |
| --- | --- |
| 项目 | 文件和 Agent 工作环境的归属单位。每个项目独享一个逻辑 Sandbox，系统为项目创建工作目录。不同项目拥有独立的文件系统和执行环境。 |
| 任务 | 侧边栏中一条可重新打开的对话。每个任务属于一个项目，并对应一个独立的 Harness 会话。同项目任务可以访问同一工作区，分别保留各自的对话上下文。 |
| 执行 | 用户发送一条消息触发的一轮 Agent 运行。一轮使用发送时选定的模型，可以包含多次工具调用，并以完成、失败或停止结束。 |

首版建议用「新建对话」作为创建入口，用「任务」作为侧边栏列表名称。每个任务可以有多轮对话，工具调用属于对应的执行轮次。

## 3. 页面与核心交互

桌面端采用左侧导航、右侧任务区的布局。左上角固定展示「新建对话」和「新建项目」。左栏按项目分组展示任务，支持展开、折叠和选中。项目按最近活动排序，组内任务按最近一轮执行排序。打开已有任务时，右栏顶部显示项目和任务，正文展示可滚动的对话，下方提供输入框和发送或停止按钮。

### 任务首页

首次进入工作台或点击「新建对话」时，右侧展示任务首页。布局参考附图，问候语「我能为你做什么？」居中，任务输入区位于下方。项目选择器放在输入区上沿左侧，点击后向上展开，列出已有项目，并在列表底部提供「新建项目」。右下角依次显示当前模型和发送按钮。模型入口旁的推理强度控件留待后续评估。

用户可以先输入任务描述或选择模型，必须选定一个已就绪的项目才能开始任务。未选项目时，输入区显示「选择项目」并禁用发送。选中后入口显示项目名称，在发送前仍可更换项目。选择或新建项目时保留已输入的描述和已选模型。

### 操作与反馈

| 用户操作 | 首版行为 |
| --- | --- |
| 新建项目 | 左上角和项目选择器使用同一个创建表单，唯一字段为项目名称，去除首尾空白后须非空。提交后，系统自动分配项目专属 Sandbox 并创建工作目录。界面显示「正在准备项目」，成功后自动选中该项目并让用户继续输入或发送。失败时保留输入并提供重试。 |
| 新建对话 | 右栏打开任务首页。已有当前项目时预选该项目并显示名称。首条消息通过校验并被服务端接受后才写入任务列表，任务标题取首条消息的简短截断。 |
| 切换项目或任务 | 在任务首页切换项目只更新草稿归属。点击侧栏项目时展示该项目最近的任务，空项目打开已选中该项目的任务首页。点击旧任务时加载历史和最新执行状态。任务开始后项目归属固定，迟到的流式输出写回原任务。 |
| 选择模型 | 点击输入区右下角的模型名称，从当前 Harness 支持且已配置可用的模型中选择。新任务预选服务端默认模型，旧任务默认沿用最近一轮的可用模型。用户可在发送前修改，本轮使用发送时确认的模型，后续轮次可以在同一任务内继续切换。 |
| 发送消息 | 项目已就绪、模型可用且任务描述非空时允许提交。提交后立即显示用户消息，右栏按顺序展示环境准备、Agent 回复和工具调用。一个项目首版允许同时执行一轮，忙碌时在同项目其他任务的输入区提示原因，其他项目可以独立执行。 |
| 停止或重试 | 停止请求传到服务端，收到停止结果后保留已显示内容并标记「已停止」。文件变更按实际执行结果保留。重试前核对上一轮状态，防止重复提交同一条用户消息或同时运行两轮。 |

聊天界面采用指定的 shadcn/ui AI Elements。`Chat` 和 `Message Scroller` 负责对话与滚动，`Message` 渲染消息，`Prompt Input` 负责输入与提交，`Model Selector` 用于切换模型，`Tool` 展示脱敏后的工具名称、状态和结果摘要。首版输入以文本为主。 [shadcn/ui AI Elements](https://ui.shadcn.com/docs/ai-elements) · [Model Selector](https://ui.shadcn.com/docs/ai-elements/base/model-selector)

## 4. Agent 执行与持久化

1. **以项目创建和恢复环境。** 创建项目时，服务端为该项目分配 Sandbox，自动创建并保存工作目录引用，完成后将项目标记为就绪。工作目录使用系统生成的稳定路径，项目名称用作界面显示。接收新任务首条消息时，服务端校验项目有效且已就绪。执行时按项目查找或恢复 Sandbox，并以同一工作目录启动 Harness 会话。项目初始化可重试，重复请求复用同一份项目环境记录，避免重复分配 Sandbox 或工作目录。
2. **以任务恢复会话。** 在项目 Sandbox 上新建或恢复该任务的 `HarnessAgentSession`。应用保存任务与会话标识、服务端恢复状态和展示用消息。Harness 保有运行时对话上下文，页面历史用于回显。AI SDK 的官方 UI 示例按 `chatId` 查找 Sandbox，Skillberry 将这层查找改为按 `projectId`，会话仍按任务恢复。 [HarnessAgent](https://ai-sdk.dev/docs/ai-sdk-harnesses/harness-agent) · [Harness UI 集成](https://ai-sdk.dev/docs/ai-sdk-harnesses/ui)
3. **按轮次流式回传。** `HarnessAgent` 输出转成 AI SDK UI 消息流，由 `useChat` 消费。服务端持久化用户消息、可展示的 Agent 输出、工具状态和本轮终态。断线或刷新后，用户可重新打开任务，查看已保存内容和最新状态。浏览器与运行中的流重新连接留待后续。 [Harness UI 集成](https://ai-sdk.dev/docs/ai-sdk-harnesses/ui)
4. **分别管理运行与环境生命周期。** 一轮完成、停止或失败后释放执行占用并记录有效会话状态。下一轮优先复用同一项目环境。Sandbox 暂停后恢复文件的能力取决于所选存储和保留期。环境无法恢复时保留对话，并明确提示文件工作区的状态。若文件仍可用但 Harness 会话无法恢复，界面提示原上下文不可用，用户可以在同项目发起新对话。 [HarnessAgent](https://ai-sdk.dev/docs/ai-sdk-harnesses/harness-agent#resuming) · [Vercel Sandbox 生命周期与持久化](https://vercel.com/kb/guide/vercel-sandbox-duration-and-persistence)
5. **按轮次应用模型。** 服务端维护所选 Harness 的可用模型清单和默认值，接收消息时校验模型并记录该轮实际使用的模型。模型失效时提示重新选择并保留输入。模型变更从下一次发送开始生效，任务继续使用原会话和项目工作目录。 [HarnessAgent 按轮次设置](https://ai-sdk.dev/docs/ai-sdk-harnesses/harness-agent#change-settings-between-turns)

项目、任务、消息和执行状态存于应用的持久化存储。项目文件留在项目工作区，Sandbox 引用、恢复状态和凭证由服务端管理。每次任务读写和执行都由服务端校验项目归属。应用密钥、内部堆栈和原始工具日志仅留在服务端，界面显示可以采取行动的错误说明。首版验收用的 Agent 操作限于专属工作区内的文件读写，凭证与网络访问按所选 Adapter 的实际需求配置。

## 5. 首版范围与 Skill 演进

首版包含项目与任务导航、自动创建项目工作目录、文本多轮对话、模型切换、真实 Harness 工具执行、工具状态展示、历史回显、执行停止和失败反馈。建议以单人内测、单一 Harness Adapter 交付，首版配置至少两个可用模型，并指定其中一个为默认模型。

后续由服务端根据项目配置，向 Harness 传入已启用的 Skill。选型时验证 Adapter 支持自定义 Skill 及附带文件。Skill 配置发生变化时，验证旧任务能否延续原会话。首版之后再定义 Skill 的安装、管理和分享，以及附件、文件管理器、团队协作与长任务后台续跑。 [Harness Skills](https://ai-sdk.dev/docs/ai-sdk-harnesses/skills) · [Adapter 能力表](https://ai-sdk.dev/docs/ai-sdk-harnesses/harness-adapters#adapter-capabilities)

## 6. 验收场景

| 场景 | 通过标准 |
| --- | --- |
| 任务首页与项目必选 | 点击「新建对话」可看到居中的问候语、输入区左上沿的项目选择器和右下角的模型入口。未选项目时，输入文本也无法发送，服务端同样拒绝缺少有效项目的请求。选定已就绪项目后发送，任务进入对应项目分组。 |
| 项目创建与工作目录 | 从左栏和项目选择器均可新建项目，表单只要求名称。完成初始化后可核对独立 Sandbox 中的工作目录已创建，新项目自动选中，已有草稿仍可提交。模拟初始化失败后重试，最终只有一份项目、Sandbox 和工作目录。 |
| 模型切换 | 右下角可在至少两个可用模型之间切换。首轮使用选定模型，下一轮可切换至另一个模型并继续同一任务。服务端记录可核对两轮分别使用的模型。选择已失效模型时，输入保留并提示重新选择。 |
| 历史导航 | 点击旧任务可打开对应的历史和最新执行状态。 |
| 真实 Agent 执行 | 在项目 A 的任务 A1 让 Agent 创建 `notes.txt` 并写入一段测试文本，界面流式显示回复和工具状态，工具执行后可核对文件内容。 |
| 项目共享与跨项目隔离 | 在 A2 读取同一份 `notes.txt`，结果一致。A2 起始消息列表为空且使用独立 Harness 会话。在项目 B 执行同样的查找，找不到 A 的文件。 |
| 多轮与恢复 | 刷新页面或重启应用后，A1 的历史可回显。在 Sandbox 保留期内暂停并恢复环境，A1 仍能基于上一轮的对话继续回答，A2 仍能读取已保存的项目文件。 |
| 停止、错误和重试 | 可停止服务端运行并在终止后发下一条消息。模拟 Sandbox 启动失败、断线或并发提交时，任务呈现相应状态，重试不会重复创建 Sandbox、重复写入同一条用户消息或启动第二个并行轮次。 |
| 环境不可恢复 | 模拟 Sandbox 或会话恢复失败。历史可查看，界面说明工作区或上下文是否可用，并展示可用的下一步。 |

## 7. 实现前待确认

| 决策 | 建议及验证点 |
| --- | --- |
| 首版发布范围 | 按单人内测评估。若首版面向多用户开放，上线前明确登录、项目所有权和各用户的资源配额。 |
| Harness、Sandbox 与模型 | 以 Claude Code Adapter 和 Vercel Sandbox 作为验证候选。用两个项目和三个任务验证自动建目录、真实文件读写、同项目多会话、跨项目隔离、服务重启后恢复以及停止后继续提问。确认候选 Harness 和账号至少可用两个模型，验证切换后的会话连续性，并确定首发模型清单与默认项。Harness 包仍处于实验阶段，验证通过后锁定依赖版本。 [Harnesses 概览](https://ai-sdk.dev/docs/ai-sdk-harnesses/overview) · [Claude Code Adapter](https://ai-sdk.dev/providers/ai-sdk-harnesses/claude-code) |
| 存储与保留策略 | 根据部署环境选持久化存储，并约定项目文件与会话保留时间、Sandbox 空闲释放条件和过期处理。明确哪些状态可以恢复，再确定界面相应文案。 |
