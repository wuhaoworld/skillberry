# Skillberry Agent 工作台需求文档

状态为评审稿 · 2026-11-24

## 1. 产品目标

用户可以新建项目，在项目内发起多个任务，让 Agent 在项目专属 Sandbox 中处理文件，并在对话中查看执行过程和结果。用户回到旧任务可以继续对话，也可以在同一项目里开启一个新任务，复用项目文件。首版先验证这条流程，为后续在项目中启用 Skill 打好基础。

当前仓库已安装 Next.js 16.4.6、AI SDK 7.0.181 和 `@ai-sdk/react` 4.0.186，shadcn/ui 使用 `base-nova`。首页仍是 Next.js 初始化页面，项目与任务存储、Harness 接入和聊天界面待建设。依据 [package.json](../package.json)、[组件配置](../components.json) 和 [当前首页](../app/page.tsx)。

## 2. 项目、任务和执行的关系

| 概念 | 首版定义 |
| --- | --- |
| 项目 | 文件和 Agent 工作环境的归属单位。每个项目独享一个逻辑 Sandbox。不同项目拥有独立的文件系统和执行环境。 |
| 任务 | 侧边栏中一条可重新打开的对话。每个任务属于一个项目，并对应一个独立的 Harness 会话。同项目任务可以访问同一工作区，分别保留各自的对话上下文。 |
| 执行 | 用户发送一条消息触发的一轮 Agent 运行。一轮可以包含多次工具调用，并以完成、失败或停止结束。 |

首版建议用「新建对话」作为创建入口，用「任务」作为侧边栏列表名称。每个任务可以有多轮对话，工具调用属于对应的执行轮次。

## 3. 页面与核心交互

桌面端采用左侧导航、右侧对话的布局。左上角固定展示「新建对话」和「新建项目」。左栏按项目分组展示任务，支持展开、折叠和选中。项目按最近活动排序，组内任务按最近一轮执行排序。右栏顶部显示当前项目和任务，正文展示可滚动的对话，下方提供输入框和发送或停止按钮。

| 用户操作 | 首版行为 |
| --- | --- |
| 首次进入 | 左栏保留两个创建入口，右栏引导用户创建项目。 |
| 新建项目 | 输入非空名称后创建项目并选中。右栏进入空对话，Sandbox 在项目首次发送消息时创建。 |
| 新建对话 | 默认归属当前项目。尚未选中项目时，引导选择已有项目或新建项目。右栏先展示草稿，首次发送消息后才写入任务列表，任务标题取首条消息的简短截断。 |
| 切换项目或任务 | 选中项目时展示该项目最近的任务，空项目进入草稿。选中任务时加载该任务的历史消息和最新执行状态。切换页面保留原任务归属，迟到的流式输出仍写回原任务。 |
| 发送消息 | 提交后立即显示用户消息，右栏按顺序展示环境准备、Agent 回复和工具调用。一个项目首版允许同时执行一轮，忙碌时在同项目其他任务的输入区提示原因，其他项目可以独立执行。 |
| 停止或重试 | 停止请求传到服务端，收到停止结果后保留已显示内容并标记「已停止」。文件变更按实际执行结果保留。重试前核对上一轮状态，防止重复提交同一条用户消息或同时运行两轮。 |

聊天界面采用指定的 shadcn/ui AI Elements。`Chat` 和 `Message Scroller` 负责对话与滚动，`Message` 渲染消息，`Prompt Input` 负责输入与提交，`Tool` 展示脱敏后的工具名称、状态和结果摘要。首版输入以文本为主。 [shadcn/ui AI Elements](https://ui.shadcn.com/docs/ai-elements)

## 4. Agent 执行与持久化

1. **以项目查找环境。** 服务端从任务归属解析项目，按项目查找并恢复 Sandbox。首次发送时创建环境并保存引用。重复请求共用同一份项目环境记录，避免一项目分配多个 Sandbox。
2. **以任务恢复会话。** 在项目 Sandbox 上新建或恢复该任务的 `HarnessAgentSession`。应用保存任务与会话标识、服务端恢复状态和展示用消息。Harness 保有运行时对话上下文，页面历史用于回显。AI SDK 的官方 UI 示例按 `chatId` 查找 Sandbox，Skillberry 将这层查找改为按 `projectId`，会话仍按任务恢复。 [HarnessAgent](https://ai-sdk.dev/docs/ai-sdk-harnesses/harness-agent) · [Harness UI 集成](https://ai-sdk.dev/docs/ai-sdk-harnesses/ui)
3. **按轮次流式回传。** `HarnessAgent` 输出转成 AI SDK UI 消息流，由 `useChat` 消费。服务端持久化用户消息、可展示的 Agent 输出、工具状态和本轮终态。断线或刷新后，用户可重新打开任务，查看已保存内容和最新状态。浏览器与运行中的流重新连接留待后续。 [Harness UI 集成](https://ai-sdk.dev/docs/ai-sdk-harnesses/ui)
4. **分别管理运行与环境生命周期。** 一轮完成、停止或失败后释放执行占用并记录有效会话状态。下一轮优先复用同一项目环境。Sandbox 暂停后恢复文件的能力取决于所选存储和保留期。环境无法恢复时保留对话，并明确提示文件工作区的状态。若文件仍可用但 Harness 会话无法恢复，界面提示原上下文不可用，用户可以在同项目发起新对话。 [HarnessAgent](https://ai-sdk.dev/docs/ai-sdk-harnesses/harness-agent#resuming) · [Vercel Sandbox 生命周期与持久化](https://vercel.com/kb/guide/vercel-sandbox-duration-and-persistence)

项目、任务、消息和执行状态存于应用的持久化存储。项目文件留在项目工作区，Sandbox 引用、恢复状态和凭证由服务端管理。每次任务读写和执行都由服务端校验项目归属。应用密钥、内部堆栈和原始工具日志仅留在服务端，界面显示可以采取行动的错误说明。首版验收用的 Agent 操作限于专属工作区内的文件读写，凭证与网络访问按所选 Adapter 的实际需求配置。

## 5. 首版范围与 Skill 演进

首版包含项目与任务导航、文本多轮对话、真实 Harness 工具执行、工具状态展示、历史回显、执行停止和失败反馈。建议以单人内测、单一 Harness Adapter 和服务端配置的默认模型交付。

后续由服务端根据项目配置，向 Harness 传入已启用的 Skill。选型时验证 Adapter 支持自定义 Skill 及附带文件。Skill 配置发生变化时，验证旧任务能否延续原会话。首版之后再定义 Skill 的安装、管理和分享，以及附件、文件管理器、团队协作与长任务后台续跑。 [Harness Skills](https://ai-sdk.dev/docs/ai-sdk-harnesses/skills) · [Adapter 能力表](https://ai-sdk.dev/docs/ai-sdk-harnesses/harness-adapters#adapter-capabilities)

## 6. 验收场景

| 场景 | 通过标准 |
| --- | --- |
| 新建和导航 | 用户能通过左上角创建项目和对话。首条消息发送后任务进入正确的项目分组。点击旧任务可打开对应历史。 |
| 真实 Agent 执行 | 在项目 A 的任务 A1 让 Agent 创建 `notes.txt` 并写入一段测试文本，界面流式显示回复和工具状态，工具执行后可核对文件内容。 |
| 项目共享与跨项目隔离 | 在 A2 读取同一份 `notes.txt`，结果一致。A2 起始消息列表为空且使用独立 Harness 会话。在项目 B 执行同样的查找，找不到 A 的文件。 |
| 多轮与恢复 | 刷新页面或重启应用后，A1 的历史可回显。在 Sandbox 保留期内暂停并恢复环境，A1 仍能基于上一轮的对话继续回答，A2 仍能读取已保存的项目文件。 |
| 停止、错误和重试 | 可停止服务端运行并在终止后发下一条消息。模拟 Sandbox 启动失败、断线或并发提交时，任务呈现相应状态，重试不会重复创建 Sandbox、重复写入同一条用户消息或启动第二个并行轮次。 |
| 环境不可恢复 | 模拟 Sandbox 或会话恢复失败。历史可查看，界面说明工作区或上下文是否可用，并展示可用的下一步。 |

## 7. 实现前待确认

| 决策 | 建议及验证点 |
| --- | --- |
| 首版发布范围 | 按单人内测评估。若首版面向多用户开放，上线前明确登录、项目所有权和各用户的资源配额。 |
| Harness 与 Sandbox | 以 Claude Code Adapter 和 Vercel Sandbox 作为验证候选。用两个项目和三个任务验证真实文件读写、同项目多会话、跨项目隔离、服务重启后恢复以及停止后继续提问。Harness 包仍处于实验阶段，验证通过后锁定依赖版本。 [Harnesses 概览](https://ai-sdk.dev/docs/ai-sdk-harnesses/overview) · [Claude Code Adapter](https://ai-sdk.dev/providers/ai-sdk-harnesses/claude-code) |
| 存储与保留策略 | 根据部署环境选持久化存储，并约定项目文件与会话保留时间、Sandbox 空闲释放条件和过期处理。明确哪些状态可以恢复，再确定界面相应文案。 |
